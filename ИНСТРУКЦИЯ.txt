───────────────────────────────────────────────────────────────
1. ЧТО ЭТО
───────────────────────────────────────────────────────────────

Учётная программа для хранения информации о технике
(компьютеры, принтеры, мониторы и пр.) по офисам, отделам,
рабочим местам. Данные хранятся в PostgreSQL.
Работает только под Windows (использует WPF и AD).

───────────────────────────────────────────────────────────────
2. ЧТО НУЖНО ДЛЯ ЗАПУСКА
───────────────────────────────────────────────────────────────

— Windows 10/11 x64
— PostgreSQL 14+ (скачать: https://www.postgresql.org/download/)
— .NET 9 SDK (скачать: https://dotnet.microsoft.com/download/dotnet/9.0)
— Если нет Visual Studio — сработает, но проще открыть проект
  в Rider или VS 2022+.

Проверить установку .NET:
    Открыть cmd.exe и набрать: dotnet --version
    Должно показать: 9.0.xxx

───────────────────────────────────────────────────────────────
3. СОЗДАНИЕ БАЗЫ ДАННЫХ
───────────────────────────────────────────────────────────────

3.1. Установи PostgreSQL, если ещё не стоит.
     В мастере установки запомни порт (по умолчанию 5432)
     и пароль для пользователя postgres.

3.2. Открой pgAdmin (ставится вместе с PostgreSQL)
     или любую консоль (команда psql).

3.3. Создай базу данных с именем:
         Inventory Data Base
     ВАЖНО: имя содержит пробел. Это не опечатка — так исторически
     сложилось, и скаффолд завязан на это имя. Если хочешь
     назвать иначе — потом поменяй строку подключения в App.config.

     В pgAdmin: правой кнопкой на Databases → Create → Database,
     в поле Database ввести: Inventory Data Base

     Или в psql:
         CREATE DATABASE "Inventory Data Base";

3.4. Создай таблицы. Открой Query Tool в pgAdmin для твоей БД
     и выполни скрипт снизу. Если нет pgAdmin — сохрани скрипт
     в файл create_tables.sql и выполни:
         psql -U postgres -d "Inventory Data Base" -f create_tables.sql

СКРИПТ СОЗДАНИЯ ТАБЛИЦ (скопируй целиком и выполни):

    -- Таблица типов устройств (Принтер, Монитор, Системный блок...)
    CREATE TABLE devicetype (
        devicetype_id INTEGER PRIMARY KEY,
        type VARCHAR(255) NOT NULL
    );

    -- Таблица моделей
    CREATE TABLE model (
        model_id INTEGER PRIMARY KEY,
        model VARCHAR(255) NOT NULL
    );

    -- Таблица офисов (кабинетов)
    CREATE TABLE office (
        office_id INTEGER PRIMARY KEY,
        officenum VARCHAR(10) NOT NULL,
        phone VARCHAR(20),
        block CHAR(1),
        department VARCHAR(255)
    );

    -- Таблица устройств
    CREATE TABLE device (
        device_id INTEGER PRIMARY KEY,
        devicename VARCHAR(255),
        ip_address VARCHAR(15),
        serialnumber VARCHAR(16),
        inventorynumber VARCHAR(16),
        note TEXT,
        dateofcommissioning DATE,
        exception BOOLEAN,
        devicetype_id INTEGER REFERENCES devicetype(devicetype_id),
        model_id INTEGER REFERENCES model(model_id),
        office_id INTEGER REFERENCES office(office_id)
    );

    -- Таблица рабочих мест
    CREATE TABLE workplace (
        workplace_id INTEGER PRIMARY KEY,
        workplace_note VARCHAR(255)
    );

    -- Связь устройств с рабочими местами (M:N)
    CREATE TABLE device_workplace (
        device_workplace_id INTEGER PRIMARY KEY,
        device_id INTEGER NOT NULL REFERENCES device(device_id),
        workplace_id INTEGER NOT NULL REFERENCES workplace(workplace_id)
    );

    -- Таблица комплектующих
    CREATE TABLE deviceparts (
        deviceparts_id INTEGER PRIMARY KEY,
        name VARCHAR(255) NOT NULL
    );

    -- Связь устройств с комплектующими (M:N)
    CREATE TABLE deviceparts_device (
        device_id INTEGER NOT NULL REFERENCES device(device_id),
        deviceparts_id INTEGER NOT NULL REFERENCES deviceparts(deviceparts_id),
        PRIMARY KEY (device_id, deviceparts_id)
    );

    -- Индекс для ускорения поиска по инвентарному номеру
    CREATE INDEX idx_device_inventory ON device(inventorynumber);

3.5. После создания таблиц вставь хотя бы одну тестовую запись,
     иначе программа при первом запуске покажет пустую таблицу:

    INSERT INTO devicetype (devicetype_id, type) VALUES (1, 'Монитор');
    INSERT INTO model (model_id, model) VALUES (1, 'Dell P2213');
    INSERT INTO office (office_id, officenum, department) VALUES (1, '101', 'Бухгалтерия');
    INSERT INTO device (device_id, devicename, inventorynumber, serialnumber,
                        ip_address, dateofcommissioning, devicetype_id, office_id)
    VALUES (1, 'Монитор Иванова', 'INV-001', 'SN-001',
            '192.168.1.100', '2024-01-15', 1, 1);

4. НАСТРОЙКА ПОДКЛЮЧЕНИЯ
───────────────────────────────────────────────────────────────

Открой файл App.config (лежит в папке проекта Wpf_Inventory_).
Найди строчку:

    <add name="InventoryDatabase"
         connectionString="Host=localhost;Port=5432;Database=Inventory Data Base;Username=postgres;Password=1911;"
         providerName="Npgsql" />

Поменяй:
    — Password=1911 на свой реальный пароль от PostgreSQL
    — Если порт не 5432 — поменяй Port
    — Если база называется иначе — поменяй Database
    — Если postgres заведён под другим пользователем — Username

ВАЖНО: Никогда не коммить App.config с паролем в git.
Если репозиторий публичный — вынеси пароль в переменную окружения
или используй .gitignore для App.config (создав App.config.example
как шаблон).

5. СБОРКА И ЗАПУСК
───────────────────────────────────────────────────────────────

5.1. Открой папку с проектом, зажми Shift, нажми правой кнопкой —
     "Открыть окно PowerShell здесь" (или cmd).

5.2. Собери проект:
         dotnet build Wpf_Inventory_.sln

     Должно выдать: "Сборка успешно завершена. Ошибок: 0"

5.3. Запусти:
         dotnet run --project Wpf_Inventory_\Wpf_Inventory_.csproj

     Или просто открой Wpf_Inventory_.sln в Visual Studio/Rider
     и нажми F5.

5.4. Если вылетает ошибка подключения к БД — проверь:
     — Запущен ли PostgreSQL (Пуск → Службы → postgresql-x64-14 → Запущена)
     — Правильный ли пароль в App.config
     — Не блокирует ли брандмауэр порт 5432
     — Создана ли база "Inventory Data Base"

7. ОСОБЕННОСТИ РАБОТЫ
───────────────────────────────────────────────────────────────

— Инвентарный номер у устройства должен быть уникальным.
  Программа проверяет дубликаты при импорте из Excel.

— Поле "Списано" (= exception) помечает устройство как
  выведенное из эксплуатации. В таблице такие строки
  подсвечиваются серо-бордовым цветом.

— Вкладка "Отделы" на самом деле показывает записи из таблицы
  office (так исторически сложилось, отделы хранятся как часть
  данных офиса). При добавлении отдела нужно указать номер
  офиса.

— Кэш (Cache.json):
  При каждом запуске программа делает слепок всех данных
  в файл Cache.json. Если сервер БД недоступен, можно
  включить режим кэша через кнопку "Fill by cache" в меню
  Файл. Кэш не предназначен для полноценной работы —
  только для просмотра последней загруженной версии.

— Вкладка "Все данные" дублирует вкладку "Устройства".
  Сделано для удобства — если нужно два взгляда на
  один список с разными фильтрами.

— Поля IP-адрес и Серийный номер имеют ограничение длины
  в базе данных (15 и 16 символов соответственно).
  Учитывай это при вводе.

───────────────────────────────────────────────────────────────
8. ЧТО ДЕЛАТЬ, ЕСЛИ ВСЁ СЛОМАЛОСЬ
───────────────────────────────────────────────────────────────

1. Удалить папки bin и obj:
       dotnet clean Wpf_Inventory_.sln
       (или вручную удалить Wpf_Inventory_\bin и Wpf_Inventory_\obj)

2. Восстановить пакеты:
       dotnet restore Wpf_Inventory_.sln

3. Пересобрать:
       dotnet build Wpf_Inventory_.sln

4. Если не помогло — удали Cache.json из корня проекта
   и попробуй снова.
